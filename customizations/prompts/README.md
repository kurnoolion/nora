# `customizations/prompts/` — per-MNO SIRA/taxonomy prompt artifacts

This directory holds the **per-MNO prompt files** generated by the
`derive-sira-prompts` skill (run via Cline on the work PC, once per
ingested MNO; see `cline-playbooks/derive-prompts.md`):

- `doc_requirement_<MNO>_<version>.txt` — batched doc-enrichment
  prompt template (placeholders `{taxonomy_block}`, `{requirements}`,
  `{max_n}`), resolved per cell by `NORA_SIRA_DOC_PROMPT_DIR`
- `query_requirement_<MNO>_<version>.txt` /
  `relevance_requirement_<MNO>_<version>.txt` — per-MNO query-time
  prompt pair (generated for consistency; per-cell selection in the
  query service is a deferred change)
- `corpus_overview_<MNO>_<version>.txt` — standalone corpus overview,
  consumed by NORA's taxonomy stage as optional prompt context via
  `NORA_TAXONOMY_OVERVIEW_DIR`

Highest version wins at resolution time; older versions stay for
provenance. Generic, redacted prompt *templates* (no MNO infix) live
in `sandbox/prompts/` instead — this directory is only for per-MNO
instances.

## Trust boundary — pre-push hook, NOT gitignore [D-062 precedent]

Per-MNO prompt files carry **real MNO names and harvested corpus
vocabulary**. This directory is NOT gitignored: files are committed
and pushed to the **company-internal** git remote so the team shares
one source of truth — the same policy as
`customizations/mappings/README.md`, enforced by the same work-PC
pre-push hook (rejects pushes to remotes whose URL contains
`github.com`; installed idempotently by
`~/work/utils/git-sync/sync-work.sh`).

If you're on a personal PC that doesn't run `sync-work.sh`, **do not
put per-MNO prompt files here** — `git push origin` would send them
to the public mirror.

## How the containers see these files

Both docker images `COPY customizations/` at build time, so after an
image rebuild the files are available in-container at
`/app/customizations/prompts`:

- `.env.sira-batch`: `NORA_SIRA_DOC_PROMPT_DIR=/app/customizations/prompts`
- `.env.nora-pipeline`: `NORA_TAXONOMY_OVERVIEW_DIR=/app/customizations/prompts`

A prompt update therefore requires rebuilding the `nora-pipeline` and
`sira-batch` images. (The overview files are hashed into the taxonomy
cache fingerprint, so the next pipeline run re-derives taxonomies
without `--force`.)
