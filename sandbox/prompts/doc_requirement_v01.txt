STEP 1 — Identify the subdomain. US MNO device specs span TWO broad families of subdomains: standards-body protocol layers (3GPP / GSMA / IETF / IEEE / OMA / SGP), AND the device's software stack and user-facing surfaces (Android platform / apps / UI / hardware). A single requirement may sit in either family, or both at once. Before generating any phrase, decide which subdomain(s) this requirement targets:

STANDARDS-BODY subdomains:
- LTE EMM/NAS — attach, detach, TAU, EMM timers (T3402/T3346/etc.), EMM cause codes, EPS bearer, PDN connectivity. Refs: 3GPP TS 24.301, TS 23.401, TS 36.331.
- LTE RRC/Access — RRC connection, RACH, PRACH, idle/connected mode, PLMN selection, cell selection. Refs: TS 36.331, TS 36.304.
- 5G NR/NAS — 5G registration, NR bands (n1-n79, n257-n261), beam management, 5G NAS, 5G PDU sessions. Refs: TS 38.300, TS 38.331, TS 24.501.
- 5G Core — AMF, SMF, UPF, PCF, NRF, NSSF, network slicing, service-based interfaces. Refs: TS 23.501, TS 23.502.
- VoLTE/IMS — IMS registration, SIP signaling, RTP/RTCP, P-CSCF discovery, voice call setup, supplementary services. Refs: TS 24.229, TS 23.228, TS 24.628, GSMA IR.92/IR.94.
- VoWiFi/Untrusted-WLAN access — ePDG selection, SWu interface, IKEv2/IPSec tunnel, EAP-AKA authentication, IMS-over-WLAN registration. Refs: TS 23.402, TS 33.402, TS 24.302, RFC 7296, GSMA IR.51/IR.61.
- WLAN/WiFi — 802.11 association, ANQP/Hotspot 2.0, WPA2/WPA3, EAP methods. Refs: IEEE 802.11, Hotspot 2.0 Release 3.
- eSIM/RSP — Profile download, EID/ICCID, SM-DP+/SM-DS, profile installation, LPA. Refs: GSMA SGP.21, SGP.22, TS.34.
- SMS — SMS over GERAN/LTE, SMS-CB (Cell Broadcast), CMAS/WEA alerts, SMSC routing. Refs: TS 23.040, TS 23.041.
- Device Management — OMA-DM, OMA LwM2M, firmware update (FOTA), bootstrap. Refs: OMA-DM 2.0, TS.42.
- Voice continuity / SRVCC — VoLTE↔VoWiFi handover, SRVCC, ePDG↔PGW path switch. Refs: TS 23.216, TS 23.402.
- Device capabilities (RF) — supported bands, power class, antenna config, SAR. Refs: TS 38.101, TS 36.101, FCC.

PLATFORM / APP / UX subdomains (these target the device's software stack and UI, NOT 3GPP-style specs):
- Android Platform / Telephony API — TelephonyManager, SubscriptionManager, ImsManager, CarrierConfigManager APIs; CarrierConfig keys (KEY_*_BOOL/INT/STRING); system properties (persist.radio.*, gsm.*, telephony.*); RIL/IMS HAL interfaces; AOSP CDD/CTS conformance; Android API level / version-specific behavior.
- Android Applications — system apps (default Dialer, Settings, Messaging, eSIM LPA), package names, Activity/Service/Receiver class names, manifest permissions (e.g. android.permission.READ_PHONE_STATE), intent actions, content URIs, default-app role assignments.
- UI / UX / strings — screen flows, settings menu paths (e.g. "Settings → Network & internet → Mobile network → Advanced"), notification channels, dialog wording, user-visible strings, accessibility, RTL behavior.
- Device hardware / modem / RF (beyond 3GPP layer) — chipset references (Qualcomm/MediaTek/Samsung Snapdragon/Dimensity/Exynos), baseband firmware, AT commands, antenna tuning, eSIM hardware, GNSS, Bluetooth, FCC certification.
- Privacy / security / regulatory — Android KeyStore, BiometricPrompt, attestation, location-privacy strings, FCC/FDA/ADA compliance.
- Carrier services / VAS — RCS Universal Profile, MaaP, RBM, jibe-style business messaging, carrier-bundled apps.

A requirement may sit purely in one family or span both (e.g., an IMS-registration requirement that also specifies the Android API to expose registration state). If it spans both, treat all relevant subdomains as in-scope for phrase generation — emit references from each.
